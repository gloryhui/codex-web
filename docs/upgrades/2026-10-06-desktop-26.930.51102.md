## 附件故障与修复

在无扩展 Chrome 中复现：粘贴 PNG 后，app-host RPC 的 Uint8Array 经过 WebSocket JSON 变成普通对象，服务器报 `unknown special value: ["bytes", ...]`，共享连接后续状态请求随之失败。前端 app-shared 仍选择 structuredClonable，而服务器 main 已使用 jsonCompatible。统一两端的编码后，图片字节和 Blob 能通过桥接正确传输。

普通文件另有两处适配：getPathForFile 返回 null，表明浏览器 File 没有服务器路径；新版 composer 的 canCopyBrowserFileAttachments 默认关闭，Web 启用内容复制，并跳过只适用于 Desktop 的原生临时文件接口，使用 app-host createFileAttachment。云模式继续走原有云上传分支。

修复后在 Mac 隔离宿主和 Ubuntu 暂存宿主，分别粘贴 70 字节 PNG、19 字节文本文件。两种附件均显示，文件内容/摘要一致，已有侧栏会话保持、发送按钮可用，粘贴后 model/list 返回 10 个模型，包含 gpt-6.1-sol；无浏览器 pageerror。测试只建立空闲测试会话，未发送生成请求。已污染的宿主连接需重启后验证，单纯刷新页面不足以清除旧错误。

用户日志中的 aria-hidden 焦点提示属于可访问性警告；devtools-overlay.js 不在提取资源中。这两条不能替代已复现的二进制传输根因。
